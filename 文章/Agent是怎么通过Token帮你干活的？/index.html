Agent是怎么通过Token帮你干活的？

Hui2026-10-192026-11-06

开头

当你打开了Codex、Claude code、deepseek harness或者其他Agent软件，在一个对话框里打了一句话：

帮我做一个新年倒计时网页

然后按下回车。

接下来十秒钟，大概是这样的：

  • 左边空白的文件列表里，”啪”地冒出一个 index.html
  • 中间的代码编辑器，一行一行的代码自己往下长
  • 命令行里跳出”运行中……”
  • 浏览器弹出来，结果是个红通通的报错
  • 编辑器自己跳到了第 12 行，代码自己补上了一个括号
  • 再运行一次，浏览器里，倒计时动起来了

而你，从头到尾只做了一件事：打了那一句话。

没有点”新建文件”，没有敲一个字母，没有点”运行”，连报错都不是你改的。

于是有三个问题，几乎是同时从脑子里蹦出来的：

刚才，是谁在打字？

是谁点的”运行”？

AI……有手吗？

这三个问题，就是这篇文章要回答的全部内容。

如果你看过上一篇《什么是 Token？AI 眼里的文字，为什么不是字？》，那你已经知道”AI 是在处理一块块 token”。这一篇就是它的下一集：我们把这十秒钟拆开，一格一格地看——一个只会”说” token 的大模型，是怎么样通过 token，把活儿一步步干完的。

如果你上一篇没看，也没关系。这篇里凡是需要用到 token 的地方，慧妈都会用一句话再给你补一遍，你顺着往下看就行。

先补一句最要紧的：

token 是 AI 处理信息的最小单位，你可以直接把它叫”块”。

AI 眼里的文字，不是一个个字，而是一块一块的积木。它读的是块，说的也是块。

这一篇你只要记住这一句就够了，剩下的不用管。

本篇你会得到什么

看完之后，下面这五件事你都能讲给别人听：

  1. 为什么聊天 AI 只能”教你做”，而 Agent 能”替你做”
  2. 大模型被关在”玻璃盒子”里是什么意思
  3. 一句需求，在 AI 内部是怎么变成”一张纸一张纸”传下去的
  4. 为什么它非要来回”转圈”，不能一步干完
  5. 为什么 Agent 干活，比聊天费 token 费得多

准备好了吗？我们从最简单的那个问题开始。

知识科普

一、先把”AI”这个字拆成两半：一个脑子，一双手

我们平时说的”AI”，其实是一个很含糊的词。要搞懂 Agent，第一件事就是把脑子里那个模糊的”AI”，拆成两样东西：

一个脑子 · 一双手

1. 脑子：那个只会说话的大模型

你平时聊天用的那个东西——DeepSeek、ChatGPT、豆包、千问——它的正式名字叫大模型（你也可以叫它”模型”）。

慧妈用一个不严谨但很好用的说法描述它：

大模型是一台”文字接龙机器”。

你给它一段话，它就一个 token 一个 token 地往后猜，猜出一段新的文字给你。它猜得非常好，好到你觉得它在”思考”。但不管它内部多复杂，它对外能做的事情只有一件：吐出 token。

注意这句话，它是这篇文章的地基：

大模型唯一的”输出”，就是一串 token。

它不会新建文件，不会敲键盘，不会点鼠标，不会运行程序。

它连”保存”都不会。

2. 玻璃盒子：它在服务器里，碰不到你桌上的任何东西

那大模型跑在哪儿？——跑在别人的机房里，跑在服务器上。

它不在你的电脑里。它没有你桌面上的文件列表，没有你的 C 盘 D 盘，看不到你的浏览器，也摸不到你的鼠标。

这里我打个比方：

💡 这就像：一位被关在玻璃房里的老师傅。你能听见他说话，他也能听见你说话，他懂的东西非常多，什么都会——但他伸手，只能摸到玻璃。

所以你在聊天框里问它”帮我把桌面上的照片按月份整理一下”，它只能回你：

“好的，你可以先新建几个文件夹，分别命名为 1 月、2 月……然后把照片拖进去。”

它讲得一点没错，甚至很详细。但活还是你自己干的。

因为它的手，被玻璃挡住了。

3. 所以，只有脑子的 AI，只能”教”你

我们把这两种体验放在一起对比，你立刻就懂了：

只有一个脑子（聊天 AI） 有脑子 + 有手（Agent）
你说”帮我做个倒计时网页” 给你一段代码，让你自己复制 自己建文件、自己贴进去
你说”帮我运行看看” 告诉你”你可以按 F5” 自己去运行，把结果告诉你
运行报错了 告诉你”可能是括号的问题” 自己找到第报错的地方，改掉，再跑一次
你的工作量 每一步都得自己动手 只在开头说一句话

看到区别了吗？

差别不在”聪不聪明”，而在”有没有手”。

二、Agent 不是”更聪明的 AI”，而是”给脑子配了一双手”

1. “手”到底是什么东西

先说结论，这句话可能有些令人难以置信，但它是真的：

Agent 的”手”，本身一点都不智能。它就是一段段普普通通的程序。

这些程序有个统一的名字，叫工具（tool）。你可以把它理解成一排按钮：

按钮（工具） 按下去会发生什么
读文件 把某个文件的内容读出来，变成文字
写文件 把一段文字写进某个文件里
运行程序 执行一条命令，把屏幕上出现的结果抓下来
上网搜 去搜索引擎查一下，把结果抓回来
打开网页 打开一个网址，把页面内容抓回来
点鼠标、敲键盘 真的去操作界面

这些”按钮”，有的是操作系统本来就有的能力，有的是工程师专门写的程序。它们没有一个会思考。

会思考的，是玻璃盒子里那个脑子。

2. 那它们是怎么配合的？

第一步：脑子”说”出一张纸条。

大模型想清楚”下一步该干什么”之后，它吐出来的 token 不是普通的聊天文字，而是一段格式很规整的文字，大意是：

你可以把它想成一张写得非常规矩的便条：上面写清楚了”用哪个工具、参数是什么”。

（不同产品这张纸条长得并不一样，有的还带着一堆你看不懂的符号。但大意永远是这两个信息：用什么、怎么用。你不用看懂格式，因为这是写给Agent看的，你只需要知道”它是在递纸条”就够了。）

第二步：Agent 的程序”读”这张纸条。

外面那个程序（也就是 Agent）看懂了这张便条，就去真的按按钮——打开文件、写入内容、保存。

第三步：Agent 把结果”写”成文字，塞回盒子里。

这段文字，会被重新送进玻璃盒子，变成大模型下一轮能读到的新 token。

第四步：脑子读完，再说下一张纸条。

就这样，一张纸条、一次动手、一张回执、再一张纸条……如此循环往复，活儿就一点点干完了。

💡 这就像：你隔着玻璃指挥一位手很巧的师傅。你不能直接碰他的工具，只能递纸条；他也不能自己决定干什么，只能照纸条做。但只要你纸条写得够细，他什么都能替你干。

3. 关键：它不会自己拿主意

这里有个特别容易被误解的地方：

很多人以为 Agent 是”一个有自己的想法、会自己规划、自己决定干多久的 AI”。

不是的。

它每一步都在等纸条。没有纸条，它就干等着。

它不知道”这个任务大概要几步”，也不知道”我是不是该收手了”，更不会在半夜突然爬起来帮你整理硬盘。它只会做一件事：

看着眼前的文字，想出下一步该干什么，然后说出来。

至于”下一步”和”下下步”之间怎么衔接、什么时候停、出错了几次要不要放弃——这些是外面那个程序（Agent）和写它的人定的规矩。

💡 一句话记住：脑子负责”想下一步”，程序负责”做这一步”，没有人负责”想全局”——除了你。

4. 所以，它俩必须组队

现在我们把两半拼起来：

一个负责”想”，一个负责”做”。

这就是为什么你只打了一句话，电脑就自己动起来了——不是 AI 长了手，是有人把一双手，接在了一个脑子后面。

三、为什么非得一步步循环着来？直接一步到位不行吗？

看到这儿，很多人会有个疑问：

既然它这么聪明，为什么不一次把整个网页写完、一次跑完？非要一轮一轮来？

三个原因，一个比一个实在。

1. 它一次只能说”一小段”

大模型每次能吐出来的 token 是有上限的。这个上限不算小，但放不下一整个项目。

一个像样的网页，HTML、CSS、JS 加起来几百上千行，换算成 token 是几万块。而它一次只能”说”一部分。

就像你让一个人一口气背完一本书——不是他不懂，是他一口气背不完。

2. 它不知道结果，就没法决定下一步

这是更根本的原因。

第 2 轮结束的时候，大模型并不知道代码能不能跑。它只知道”我写完了”。

在不知道结果的情况下，它没法决定下一步该干什么——是继续加功能？还是先修 bug？还是已经可以交付了？

所以它必须停下来，等回执。

回执没回来之前，它就是个”等消息的人”。

💡 这就像：你打电话教电话那头的朋友开你家抽屉。你说”先开左边第一个”，他开完告诉你”开了，里面有个盒子”，你才能说”把盒子拿出来”。你不可能一口气说完五十步——因为你不知道每一步做完之后，现场变成什么样了。

3. 活儿越长，越容易”跑偏”

还有一个现实问题：轮数一多，它就容易忘事、绕圈、重复。

原因我们后面会讲——跟 token 的”账”有关。你现在只需要知道：

Agent 干活，本质上是一个”必须反复确认”的过程。

不是设计得笨，是它天生就只能这样干。

4. 所以，”会拆步骤”比”聪明”更重要

这句话你可能想不到，但它特别重要：

Agent 干得好不好，很大程度不取决于脑子多聪明，而取决于”每一步拆得够不够小”。

每一步足够小，它就能一步一确认，错了马上改。
每一步太大，它就容易一口气错到底。

这也是为什么你用 Agent 的时候，”把话说清楚、把任务说小”特别管用。

四、同一个圈，能干的事远不止写代码

写代码只是最好演示的一种。因为这个圈是通用的。

同样这四步，换成别的事，一样转：

你说的话 它转的圈
“把第三段改正式一点” 读文档 → 改那一段 → 存回去 → 检查有没有改坏
“把照片按月份整理好” 列出照片 → 读拍摄日期 → 建文件夹 → 一个个移动
“帮我查一下明天的天气” 搜索 → 打开网页 → 抄下天气 → 回答你
“把这份表格做成图表” 读表格 → 算数 → 生成图 → 存成文件
“盯着这个网页，降价了告诉我” 定时打开 → 读价格 → 比较 → 通知你

看出来了吗？它们的骨架，是同一个：

说一步 → 做一步 → 看结果 → 再说下一步

写代码是它，改文档是它，整理文件是它，查资料还是它。

你以后看到任何”AI 助手”、”AI 智能体”、”AI 打工”之类的宣传，只要它在”自己动手做事”，背后几乎都是这个圈。

五、那 token 到底花在哪儿了？

好，原理讲完了。现在讲一个跟你的钱包直接相关的问题。

很多人第一次用 Agent 会觉得奇怪：

我就问了一句话，怎么感觉比聊天费这么多？

因为 Agent 每转一圈，都在花钱。而且越转越贵。

1. 每一轮，它都要”重读一遍”

这是最反直觉、也最要命的一点。

大模型没有记忆。它不像人，聊完了还记得。它每次被调用，都是从零开始看一遍别人递给它的全部文字。

那”全部文字”包括什么？

每一轮它要读的东西 说明
身份说明 开头那段”你是一个编程助手，你可以使用以下工具……”
之前的全部对话 你说的每一句、它说的每一句
之前的全部回执 每一次”已创建”、”已写入”、”报错在第 12 行”
这一轮的新回执 刚刚发生的那件事

注意：这些全部要重新读一遍，全部要重新算钱。

第 1 轮，它读一小段。
第 2 轮，它读”一小段 + 第 1 轮的全部内容”。
第 3 轮，它读”一小段 + 前两轮的全部内容”。
……

这就是”越转越贵”的来源。

💡 这就像：每干一步，都要把前面所有的工作记录重新念一遍给你听。干到第十步的时候，光”念记录”就比干活本身费时间。

2. 为什么 Agent 比聊天贵那么多

我们把两种用法摆在一起：

普通聊天 Agent 干活
你发多少字 一次 一次
模型被调用几次 1 次 可能几十次
每次要读多少内容 你这段话 你这段话 + 全部历史 + 全部回执
输出多少 一段回答 每轮都要输出纸条、代码、说明

同样一个问题，聊天是”一次买卖”，Agent 是”几十次买卖，而且每一次都比上一次更贵”。

所以你看到的现象就都能解释了：

  • 为什么 Agent 干一个活儿，账单比聊天高一个数量级
  • 为什么它干到一半会突然变慢（前面要读的东西太多了）
  • 为什么长任务干到后面，它会开始忘事——不是它笨，是前面塞的东西太多，把”白板”占满了

小知识：上一篇讲过的”上下文窗口”，在这里就变成了一个很具体的问题——Agent 转的圈越多，那块”白板”就越挤。 挤满了，最早的内容就得被挤出去，它就开始”失忆”。

3. 一张示意账单（不是精确数字，看结构就行）

下面这张表，因为不同模型、不同工具差得太远。所以我们只需要看个大概，仅作参考即可：

每一轮烧钱的地方 大致量级
身份说明（每次都重读） 一两千token，每轮都付
历史记录（越滚越长） 每轮都在涨
你的需求 可能几十token，很便宜
回执（报错信息可能很长） 从几十到几千token都有可能
它吐出来的内容（输出更贵） 通常比输入贵好几倍

结论：一次完整的 Agent 任务，token 消耗常常是”同样问题问一次聊天 AI”的十倍以上——具体多少，取决于它转了多少圈。

重要提醒：你平时用的大部分 AI 产品（包括各种”AI 编程助手”），并不会把 token 账单摊给你看——它们要么包月，要么按”次数”扣额度。但后台算的，就是这笔账。 所以你才会看到”用着用着额度就没了”。

4. 三个能立刻省钱的习惯

关于如何使用Agent才能更省钱，这边慧妈直接给你三条有用的建议：

第一条：把任务说小、说清楚。

对比一下：

第二种，它可能 3 轮就干完了。
第一种，它可能先问你三个问题，再猜你的意思，转十圈，最后做出来的还不是你要的。

你省下的每一圈，都是真金白银。

第二条：让它先说计划，再动手。

这是一个反直觉但特别有用的技巧。

在让它干活之前，先说一句：

先别动手，把你打算怎么做，分几步告诉我。

它吐一份计划，大约几百个 token，很便宜。你看一眼——如果方向错了，这时候叫停，你只损失了几百 token。

如果方向对了，你再让它干。这一步，能帮你省掉后面一大半白转的圈。

第三条：简单的事，别用 Agent。

  • 想查个概念、写段文案、翻译一段话 → 聊天就够了
  • 想改你电脑上的文件、想跑程序、想操作网页 → 才需要 Agent

用牛刀杀鸡，不是不行，是费钱。

第四条：最省钱的一条

直接不使用AI就行了，不使用就不花钱，肯定省钱啊🤪

六、几个你一定会好奇的问题

问：Agent 不就是”自动点鼠标的脚本”吗？

答：不是。

脚本是”写死了的”：第一步点这里，第二步点那里，遇到意外就卡住。

Agent 是”每一步现想”的：它看到报错，会换一种方法再试；看到页面变了，会重新判断该点哪儿。

脚本不会想，Agent 每一轮都在想。

（当然，代价就是——它比脚本慢，比脚本贵，而且有时候想歪。）

问：它会不会”假装”干完了？

答：会。而且这是它最讨厌的毛病之一。

因为大模型只是在”猜下一句最像样的话”。当它猜”任务完成了，我该说完成了”的时候，它可能根本不知道到底完成没有——它只是觉得这句话很合理。

所以你会遇到：它说”已经帮你改好了”，你一看，文件根本没动（奇怪，怎么有点像你豆姐🤣）。

🤔 判断方法：别听它说，去看结果。

文件真的变了吗？程序真的跑通了吗？网页真的打开了吗？

它的话是”转述”，不是”证据”。

问：为什么它有时候会绕圈、死循环？

答：三个常见原因：

  • 同一个报错反复出现，它每次都想”再试一次”，但没想到换个思路
  • 它看不到自己的进度，以为自己还没开始
  • 上下文挤满了，前面试过什么它已经忘了，于是又试一遍

所以几乎所有 Agent 都有个隐藏设定：最多转多少圈就强制停下。 这个”上限”，就是防它转到天荒地老的。

问：它会不会把我文件删了？

答：有可能。

它有”写文件”这只手，那”删文件”、”覆盖文件”通常也在能力范围里。而且它不理解什么叫”重要”——在它眼里，一个文件和一个备份文件没有区别。

所以第一次用 Agent，慧妈的建议很朴素：

  • 先在没用的文件夹里试
  • 重要的东西，先备份
  • 别一上来就让它整理你的整个 D 盘

问：它是不是真的”看见”网页了？

答：这个问题问得特别好。

大多数情况下，它没”看见”，它读到的是网页被转成的文字。
少数会截图的 Agent，它”看见”的也是被切成一块块 token 的图片。

从头到尾，它都没有眼睛。它只有”递进来的文字”。

问：我完全不懂代码，能用吗？

答：能，而且你比程序员更需要它。

但有一件事你得接受：你得能判断”它干得对不对”。

它做完一个网页，你要能打开看看长得对不对；它整理完照片，你要能翻一翻有没有放错。

你不需要会写，但你得会验收。 这句话，希望你记一辈子。

问：那我把活儿全交给它，不就完了？

答：先别。

它有手，但它不会替你想”这事儿该不该做”。

方向是你定的，验收是你做的，责任也是你的。 它只是个执行力特别强、但完全没有主见的帮手。

七、注意事项：第一次用 Agent，请守住这几条

前面讲的都是”它怎么干活”，这一节讲”你怎么不出事”。

因为有手的东西，和有脑子的东西，风险完全不一样。

1. 权限，能少给就少给

让它只能碰一个文件夹，就别给它整个硬盘。
能用”只读”的，就别给它”可写”。

💡 这就像：你请人来家里修水管，你会把整串钥匙给他吗？

2. 密码、密钥，一个字都别给它

它读到的每一个字，都会变成 token，都可能被发到服务器上。

记住一句话：凡是你不愿意贴在公网上的东西，都别贴进对话框。

3. 重要操作，让它先说再做

删文件、改系统设置、发邮件、下单、转账——这类事，先让它把”打算做什么”写出来给你看。

4. 一定要验收

它说”完成”，你去看结果。
它说”测试通过”，你自己点一下。

它是执行者，不是担保人。

5. 给它一个”止损线”

长任务开始前，先跟它说清楚：

最多试 5 次，5 次还不行就停下来告诉我。

不然它可能在一个小坑里，转到你的额度烧完。

结语

好了，以上便是本期教学的所有内容了。

我们回到开头那三个问题。

刚才，是谁在打字？

是 Agent 的程序。 它照着大模型吐出来的纸条，一个一个字符地敲进去。

是谁点的”运行”？

还是 Agent。 大模型只说了”运行一下”，真正按下那个按钮的，是程序。

AI……有手吗？

没有。

大模型没有手。它被关在玻璃盒子里，碰不到你的任何东西。它能做的，只有说。

但它身边站着一个有手的东西。 那个东西叫 Agent。

而它俩之间来回递的，不是眼神，不是手势，不是”感觉”——

是一张一张的纸条，一个一个的 token。

所以这篇文章，如果只能留一句话给你，慧妈希望是这句：

AI 没有手。它只是用 token，指挥了一双别人的手。

而想通这件事之后，很多原本莫名其妙的现象，就都对上了：

  • 为什么它必须一轮一轮来（因为不看到回执，它不知道下一步）
  • 为什么它看不见报错却知道改哪儿（因为报错被抄成文字递进去了）
  • 为什么它有时候会”假装”干完了（因为它只是在猜下一句最像样的话）
  • 为什么它干活比聊天贵那么多（因为每一轮都要把前面全部重读一遍）
  • 为什么它干到后面会忘事（因为上下文被塞满了）

你以为它在”看”你的电脑，其实它只是在”读”别人递给它的字。
