AI时代，什么是API key？

Hui2026-11-142026-11-23

开头

上周，一个朋友给我发来三行字：

我装了个 AI 软件
它让我填两个框
我填了，一直报错

我让他截个图。是这么两个输入框：

设置 · 模型服务

他补了一句，我印象特别深：

“这两个框，我盯着看了半个钟头。”

base URL？API key？

每个字母我都认识，拼在一起像外星话。上网一搜，能搜到的解释是这样的：

“API Key 是用于身份验证的凭证，Base URL 是接口的基础路径。”

好，这回连每个字都认识了，还是不懂。

所以我打算换个讲法。不说“凭证”，不提“接口”，也不用“鉴权”这种词。 就当你是我那个朋友，坐下，我们一个一个填。

看完这篇你会明白三件事：

  • 这两个框里，到底装的是什么
  • 为什么它们必须凑在一起才能用
  • 填错、填漏、填给别人看，分别会出什么事

（放心，这篇不长。慧妈写它，就是为了让那个盯着两个框看半小时的人，少盯一会儿。）

知识科普

一、说白了，就两样东西

1. 一把钥匙，一块门牌

如果非要给这两个框各配一个实物，我会这么配：

API key，是那把钥匙。
base URL，是那块门牌号。

就这么简单。

对应什么 管什么
API key 钥匙 让不让你进
base URL 门牌号 你去敲哪扇门

一个决定让不让你进，一个决定你去哪儿敲。

缺一个都不行：只有钥匙没门牌，你站在大街上掏钥匙；只有门牌没钥匙，你找到了门，进不去。

2. 那为什么非要分成两个框？

这是很多人没想通、但一想就通的地方。

因为这两样东西，一个是公开的，一个是私密的。

  • 门牌号是公开的。 所有 AI 厂商的地址，都明明白白写在他们自己的官方文档里，谁都能看、谁都能抄。
  • 钥匙是私密的。 那串东西只有你有，一旦别人拿到，花的钱算你的。

所以软件把它们分成两个框——一个可以抄，一个只能你自己去领。

还有一个更实在的原因：

换模型，只换上面的框；换账号，只换下面的框。

从 A 家换到 B 家，改一行地址就行，钥匙不动；换一个号，改一行钥匙就行，地址不动。

分开，是为了让你换东西的时候不用连锅端。

二、门牌号：base URL 到底在写什么

1. API 是什么？是人家在墙上给你开的一扇窗

API 这个词的全称，你不需要记。你只需要知道它长什么样：

它是人家在墙上给你开的一扇窗。

你把问题从窗口递进去，对面替你把活干了，再把结果从窗口递出来。

你进不去那栋楼。你看不见里面有几台机器、几个工程师。你也翻不了人家的抽屉。

这就是它为什么叫“窗”，不叫“门”。 门是让你进去的，窗只是让你递东西的。

这也就解释了另一件事：API 不是“更厉害的网页”。 网页是给人看的，API 是给程序看的。同一个模型，网页版给你一个聊天框，API 给你的是一扇只认格式的窗——你递进去的东西格式不对，它原封不动退回来。

2. 这扇窗的地址，长这样

好，看门牌。

AI 的收货地址，一般长这样：

第一次看到这串东西，人的本能是“这什么玩意儿”。但按斜杠切开，就是四截：

一截一截看：

第一截 https:// —— 用什么方式联系。

https 就是“加密送信”，路上有人拆开看，看到的也是乱码。少了那个 s（写成 http://），很多家会直接拒你，或者给你一个“连接不安全”的红叉。

第二截 api.example.com —— 哪家公司。

这是整串里唯一“换一家就变一次”的部分。注意前面那个 api：它通常表示“这栋楼的 API 入口”，不是你平时用浏览器点开的那个官网。一个公司往往有好几个门，别走错。

第三截 /v1 —— 第几层。

v1 就是第一版。有些家没有这一截，有些家是 /v2、/v4。写错楼层，你敲的就是别人家的门。

第四截 /chat/completions —— 找哪个柜台。

chat 是聊天，completions 是“接着往下写”。合起来就是“帮我把这段话说下去”的那个柜台。

同一栋楼里还有别的柜台：/embeddings 是“把文字变成一串数字”，/images/generations 是“画图”。地址里不带柜台，门卫不知道该把你领到哪儿。

一句话记住：前面是寄到哪儿，后面是找谁办。

3. 少一个字，包裹真的会绕地球三圈

我知道“少一个字就送错门”听着像吓唬人。但它真的会发生，而且发生得特别频繁。

你以为的小毛病，在对方看来是“我们这儿没这个柜台”。

最坑的地方在于：它不会告诉你“地址写错了”。 它只会甩给你一个 404，或者一句 Not Found。新手看到这四个字，第一反应往往是“我 key 是不是有问题”——然后开始怀疑钥匙，其实钥匙一点毛病没有。

所以这条经验你现在就能记下：

报错先看是 4 开头的哪个数。404 是地址，401 是钥匙。

想看看真实的门牌号长什么样？

前面那个 api.example.com 是我编的，专门用来举例——它不是任何一家公司，你也不用去访问它。

真实世界里，几家常见的门牌大概是这样（只到“哪栋楼”这一层）：

谁家门牌号（示意）
OpenAIhttps://api.openai.com/v1
DeepSeekhttps://api.deepseek.com
阿里云百炼https://dashscope.aliyuncs.com/compatible-mode/v1
智谱https://open.bigmodel.cn/api/paas/v4

看出来了吗？楼长得完全不一样，结构却一模一样：协议 ｜ 公司 ｜ 楼层 ｜ 柜台。

还有一行，是我觉得最有意思的：

你在自己电脑上跑模型：http://127.0.0.1:11434/v1

127.0.0.1 的意思是“这台电脑自己”。

对，这一次门就开在你自己屋里——所以它可以没有钥匙，也不花钱。 这是整套规则里唯一的例外，第三节会说为什么。

各家路径、版本号、要不要写 /v1，都以官方文档为准，别照抄这篇。

三、钥匙：API key 不是密码

1. 它长什么样

门牌讲完，看钥匙。

API key 一般长这样：

一长串，看着像乱码。

几个你可能会注意到的细节：

  • 前面总有个 sk-。 这是行业里的老习惯，sk = secret key。有的公司后面还接 proj-、ant- 之类，那是“这把钥匙配给哪个项目用的”。
  • 长度各家不一样，三十几位到五十几位都有。
  • 它不是随便生成的。 前缀、长度、里面藏的标识，各家有各家的规矩。所以对方拿到这串，能查出“这钥匙谁发的、什么时候发的、用掉多少”。

但别被它那副乱码脸骗了——它不是密码。

2. 密码证明“你是你”，它证明“你能用”，还记账

这是这一节最重要的一句话：

密码回答的是“你是不是这个人”。
API key 回答的是“你有没有资格用、已经用了多少”。

听着像，其实差得远。

网站的密码 API key
证明什么 你是你 你能用
谁在用 人 程序
用一次会怎样 没记录 记一笔账
能设过期吗 一般不能 可以
泄露了怎么办 改密码 作废重发，旧的立刻失效

看最后一行——这是 key 比密码强的地方，也是很多人不知道的地方。

钥匙丢了，你不用换锁。把那张卡注销，重新发一张，旧的那张当场作废。十秒钟的事，不用通知任何人。

所以它更像一张门禁卡。

刷一下，门开了，也记了一笔账。

公司前台能查到“这张卡今天刷了 37 次，都在下午两点到五点”——你的 AI 账单也一样，每一笔都记着花在哪个模型、哪个时间。

3. 顺手破一个最常见的误会

讲 key 之前，得先把一个东西按住，不然后面全乱。

很多人以为：我装了个 AI 软件，AI 就在我电脑里。

不是。

AI 根本不在你电脑里跑。

你这台电脑，就算装了张挺好的显卡，也跑不动一个正经的大模型——那玩意儿是几百 GB 的“知识”，塞进你那 16G 内存里，连装都装不下。

真实情况是：

你只是打了个电话。

你按下发送，软件把你那句话打包，通过网络送到人家的机房，人家的显卡算完，再把结果送回来。

你电脑里那点算力，只够显示一个打字动画。

所以：

  • 门牌号 = 电话号码，打给谁
  • API key = 电话卡，这通电话记在谁账上
  • 你电脑里的软件 = 话筒

这就是为什么必须联网。 断网了，钥匙再对、地址再准也没用——电话打不出去。

（折叠里那个 127.0.0.1 是唯一的例外：那是你给自己家装了一部内线电话，所以不用卡，也不花钱。）

四、两样凑在一起，到底发生了什么

1. 跟着一封信走一趟

前面都是拆开讲。现在装回去，看看你按下“发送”的那几秒钟，究竟发生了什么。

我们跟着一封信，走一遍：

一封信的旅程

一、把问题写成信

你打的字，被软件打包成一封信。

信里写的不是光秃秃一句话，而是：谁问的、问的什么、要什么格式的回答、要不要长一点。这些你一个字都没填，软件替你填了。

这一步你永远不用管。

二、信封上写地址

把 base URL 写在信封上。

对应你设置页里上面那个框。

地址错了，这封信在门口就被扔了，连拆都不会被拆。

三、信背面贴钥匙

把 API key 贴在信封背面。

对应你设置页里下面那个框。

注意：钥匙是贴在背面的，不是写进信纸里的。 这个区别很重要——收信的人看得见钥匙，可钥匙不会混进正文，也不会被当成内容念出来。

四、到了门口，先过门卫

信到了，门卫不急着拆。

他先问三句：

这钥匙是真的吗？ 假的、错的、作废的，退回。（这就是 401）

这账户还有钱吗？ 没了，退回。

今天是不是刷得太猛？ 太频繁了，退回。（这就是 429）

三句全过，才拆信。

拆开之后，钥匙被摘下来收好，信纸交给柜台后面那个模型。

五、算完，原路寄回

模型读完信，一个字一个字往外写，写完打包，沿着原路送回来。

你屏幕上那个字一个个往外蹦的动画，就是这封信在路上走的样子。

2. 这里藏着一个让人安心的细节

上一段我特意写了句“钥匙被摘下来收好，信纸交给模型”。

这句值得单独拎出来说。

模型不知道你的钥匙。

门卫看完就把钥匙收走了，模型见到的只有信纸。所以那个很多人偷偷担心的问题——

“AI 会不会记住我的 key，哪天拿我的 key 去干别的？”

不会，它连见都没见过。

（当然，发 key 的那家公司是见过的，它必须见，不然没法给你记账。所以“别把 key 交给来路不明的第三方”这句话依然成立。两件事不矛盾。）

3. 软件里那两个框，其实就是代码里这两行

只用图形界面的朋友可以跳过这段。

但我还是想让你看一眼，因为看懂这一眼，那两个框就再也不会神秘了。

你在某个 AI 客户端的设置页里，填的就是这两行：

点保存，软件自己会把它们塞进每一封信里。

同一件事，用代码写出来是这样：

看那两个参数名：base_url 和 api_key。

一模一样的两样东西，一个用手填，一个用代码填。

所以以后不管在哪个软件、哪篇教程、哪份文档里看到这两个词，你都可以在心里翻译成：

“填地址”和“填钥匙”。

五、四个坑，别让钱包替你交学费

原理懂了，说几个真会让人吃亏的。

1. 钥匙别乱给

它一泄露，别人刷的是你的卡。

最常见的泄露方式不是被黑客偷，是你自己发出去的。

真实场景：程序报错了，你把截图甩进群里问“这什么情况”。截图里那串 sk- 开头的字，清清楚楚。

那串字是活的。 谁复制走，谁就能用你的额度。

所以发图之前，养成一个习惯：

钥匙只露前 6 位、后 4 位，中间涂掉。

这样别人能帮你确认“是不是这把”，但拿不走。

2. 地址别写错

少一截，直接 404。

这条前面讲过了，只补一句实操：

别凭记忆手打，复制粘贴。

那串地址里有连字符、有斜杠、有版本号，手打十次能错三次，而且错了还看不出来——completions 和 completion，就差一个字母，肉眼几乎发现不了。

3. 别把钥匙写进网页里

这条最要命，也是新手最容易犯的。

如果你自己做了个网页，或者用某个“一键建站”工具搭了个 AI 聊天页，然后把 key 写在了网页代码里——

那等于把钥匙插在门上，还顺手把门敞开给全世界。

为什么这么严重？

网页的代码是下载到你浏览器里运行的。

任何人打开你的网页，按一下 F12，就能看见里面所有的东西——包括你写死的那把钥匙。

这不是“藏得深不深”的问题，是它一定会被下载到别人电脑上的问题。

正确做法：key 放在服务器上，让服务器替你去发这封信。 网页只跟你的服务器说话，永远不碰钥匙。

这也是为什么“做个 AI 网站”没想象中那么简单——不是难在页面，是难在这道墙。

4. 别用共享的、来路不明的 key

网上总有人分享“免费 key”“公共 key”，或者拉你进个群说“用这个，随便刷”。

用之前先想一秒：

你发过去的每一句话，都要经过一台不属于你的机器。

你的问题、你贴进去的资料、你上传的文件，在那台机器上都是明文。

反过来也一样——那把钥匙是共用的，别人也能看见“共用这把钥匙的人”在问什么。

（上一篇《为什么中转站提供的AI模型那么便宜？》讲过这类生意的底层逻辑，有空可以翻翻。核心就一句：你看不见的那一层，才是你要付的代价。）

六、几个你一定会好奇的问题

问：我在网页版聊天，为什么从来不用填这两个框？

答：因为那家公司替你填好了。

网页版的钥匙存在人家自己的服务器上。你登录用的账号密码，证明的是“你是这个账号的主人”，跟 API key 是两码事——一个给人用，一个给程序用。

问：那我要不要也去申请一把 key？

答：看你干什么。

只在网页上聊天，用不着。想让别的软件接上 AI（第三方客户端、各种插件、你自己写的小工具），就必须有一把。没它，那些软件没法证明“这次调用该记在谁账上”。

问：免费的 key 和付费的 key，差在哪儿？

答：同一把锁，额度不同。

免费那把通常限速、限量、能用的模型少。够你试水，不够你干活。

问：报错看不懂怎么办？

答：记住四个数就行。

看到这个 多半是 先检查
401 钥匙不对 key 有没有抄错、是不是已经作废
404 地址不对 base URL 有没有多字少字、结尾斜杠
429 用得太猛，或者没额度了 是不是刷太快；账户余额
400 信写得不对 模型名字写错、参数格式不对

一条经验：先看第一个数字。 4 开头是“你这边有问题”，5 开头是“它那边有问题”。

问：我明明填对了，为什么还是连不上？

答：那可能跟这两个框都没关系。常见的三种：网络不通（有些厂商的接口在你所在地区直连不上）、代理没配好（软件走了代理，但代理不走这条路）、地址忘了带端口（本地跑的模型经常要写 :11434 这种端口）。

排查顺序：先用浏览器直接打开那个 base URL，看有没有返回东西。能打开，说明路是通的，问题在钥匙；打不开，问题在路上。

问：key 会过期吗？

答：可以设，也可以随时手动作废。

大部分平台都支持“给这把钥匙设个有效期”和“立刻注销”。建议每台设备、每个用途单独发一把，并且起个名字——哪天某台机器不用了，注销那一把就行，别的都不受影响。

七、三件现在就能做的事

不用记太多，就三件。

第一件：把钥匙存进该存的地方。

别存微信收藏，别存桌面那个叫“新建文本文档.txt”的文件。

用密码管理器，或者至少用一个加密的笔记。如果某台电脑上某个软件要用它，那就存在那个软件的设置里，别再另存一份。

第二件：一把钥匙只干一件事。

每台设备、每个用途单独发一把，起个能看懂的名字：

  • 家里的台式机
  • 笔记本
  • 那个报错的小工具

哪天账单不对劲，名字一看就知道该注销哪一把。

第三件：每个月看一眼用量。

不是让你抠钱，是让你知道自己在花什么。

账单突然涨了一截，只有两种可能：你用得多了，或者有一把钥匙在你不认识的地方被用了。前者无所谓，后者越早发现越好。

结语

好了，以上便是本期教学的所有内容了。

回头看，这篇文章其实只讲了一件事：

那两个框，一个是门牌，一个是钥匙。

想通这一件事，前面那些莫名其妙的现象就全对上了：

  • 为什么非要分成两个框（门牌能公开，钥匙不能）
  • 为什么地址少一个字就 404（这栋楼没这个柜台）
  • 为什么 key 不是密码（它不证明你是谁，它证明你能用，还记账）
  • 为什么丢了 key 不用慌（作废重发，旧的当场失效，不用换锁）
  • 为什么必须联网（AI 不在你电脑里，你只是打了个电话）
  • 为什么不能写进网页（网页代码是下载到别人电脑上跑的）
  • 为什么别用共享 key（你说的话要经过一台不属于你的机器）

而门卫问的那三句，其实也可以套到你自己身上：

钥匙对不对、钱够不够、用得猛不猛。 你遇到的绝大多数报错，都是这三句里有一句没过。

最后，还是那三个词：

词 填什么
地址 base URL
钥匙 API key
门 门后面，才是那个能帮你干活的 AI

这几篇是连着的，按顺序看最顺：

《什么是Token？》 讲 AI 怎么数你的字、怎么算你的钱；
《Agent是怎么通过Token帮你干活的？》 讲 AI 怎么长出双手；
《为什么中转站提供的AI模型那么便宜？》 讲你手里这把钥匙，是从哪儿来的；
这一篇，讲的是你怎么进门。

四篇连起来，一个完整的“AI 是怎么被你用上的”，就齐了。

本文数据说明

文中 api.example.com 是举例用的假地址，不指向任何真实服务；sk-8f3c1d7a… 那串 key 也是编的，全文没有出现任何一个真实密钥。

sk- 前缀是行业里常见的写法，不是硬性规定，各家规则不同。key 的真实长度、能不能设过期、作废后是否立即失效，以各家官方文档为准。

折叠里那几家厂商的门牌号，是写作时公开文档里的示意值，路径、版本号、要不要写 /v1 都可能变，别照抄，以官方当期文档为准。

401 / 404 / 429 / 400 是 HTTP 的标准状态码，多数厂商遵循，但“余额不足”具体报哪个码各家不一样，有的报 429，有的报 402。看报错内容，别只看数字。

代码示例里的 model="某个模型的名字" 需要换成各家真实的模型名，直接运行是跑不通的。
